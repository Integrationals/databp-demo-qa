1. Purpose and grounding recap

This guide implements Entitlement and billing reconciliation: design document, knowledge 111 item 806 v41 and does not relitigate its decisions.

Design decision Settled rule used by the implementation
D-2 The checks compare license, entitlement, usage report and invoice per subscriber, product and month
D-8 The answer key is the expected result: a test requires the table to find exactly its rows
D-10 The fifth check, entitled beyond reported, prices at risk the units an under-reporting audit would test
D-12 An absent document counts as zero units
D-16 Void invoices are not billing; invoice_item_metric already excludes them
D-21 Gold tables are named by suffix
D-22 subscriber_product_month_metric is the nested-aggregation exception: each row keeps its own result for each check, and MetricFlow sums the rows

Code in this guide is an illustrative pattern: more than pseudocode, less than shipping code. Do not copy it into the repo; implement it against the branch. Development is done when the output is shown correct against real data, per K#12 I#26.

5. Ordered implementation steps

Step 1. The exception reads four documents (models/marts/subscriber_product_month_metric.sql)

Extends the nested-aggregation exception of D-22 (Data Mart Design Principles, knowledge 12 item 104). Each document table is summed to the subscriber, product and month; the grain is the union of their keys; each document joins to it, absent counting as zero (D-12); the product's unit price comes from product_dim. The five checks follow the answer key's definitions (D-8): three by units, two by the presence of a document. Expected movement: rows with only an entitlement or only a billed item are added; every row present before keeps its licensed and reported units and its two columns (B-2). Exemplar: the file at 4e6cb23. The model as built:

-- Gold subscriber_product_month_metric: one row per subscriber, product and month that has a license,
-- an entitlement, a usage report or a billed invoice item. Absent counts as zero units (D-12).
-- Registered exception under Data Mart Design Principles (k12ki104): nested aggregation.
-- Each row's check columns are a per-row reduction that MetricFlow then sums across rows (D-22).
-- Unit tests: ut_subscriber_product_month_two_sides and ut_check_*. Layer 6: assert_subscriber_product_month_reconciles.
-- Layer 4: assert_checks_match_answer_key.
-- Retires when MetricFlow can sum a difference taken per subscriber, product and month across those
-- groups in one metric; the metrics then read the four document tables directly.
{% set documents = [
    ('license',     'license_line_month_metric', 'licensed_units'),
    ('entitlement', 'entitlement_month_metric',  'entitled_units'),
    ('report',      'usage_report_metric',       'reported_units'),
    ('billing',     'invoice_item_metric',       'billed_units'),
] %}
with
{% for name, model, units in documents %}
{{ name }} as (
    select client_hk, subscriber_hk, product_hk, usage_month, sum({{ units }}) as {{ units }}
        {%- if name == 'billing' %}, sum(billed_amount) as billed_amount{% endif %}
    from {{ ref(model) }}
    group by client_hk, subscriber_hk, product_hk, usage_month
),
{% endfor %}
grain as (
    {% for name, model, units in documents %}
    select client_hk, subscriber_hk, product_hk, usage_month from {{ name }}
    {% if not loop.last %}union{% endif %}
    {% endfor %}
),
joined as (
    select
        grain.client_hk,
        grain.subscriber_hk,
        grain.product_hk,
        grain.usage_month,
        license.subscriber_hk is not null       as has_license,
        entitlement.subscriber_hk is not null   as has_entitlement,
        report.subscriber_hk is not null        as has_report,
        billing.subscriber_hk is not null       as has_billing,
        coalesce(license.licensed_units, 0)     as licensed_units,
        coalesce(entitlement.entitled_units, 0) as entitled_units,
        coalesce(report.reported_units, 0)      as reported_units,
        coalesce(billing.billed_units, 0)       as billed_units,
        coalesce(billing.billed_amount, 0)      as billed_amount,
        product.unit_price
    from grain
    {% for name, model, units in documents %}
    left join {{ name }}
        on {{ name }}.subscriber_hk = grain.subscriber_hk
       and {{ name }}.product_hk = grain.product_hk
       and {{ name }}.usage_month = grain.usage_month
    {% endfor %}
    left join {{ ref('product_dim') }} as product
        on product.product_hk = grain.product_hk
)

select
    md5(subscriber_hk || '|' || product_hk || '|' || cast(usage_month as varchar)) as subscriber_product_month_hk,
    client_hk,
    subscriber_hk,
    product_hk,
    usage_month,
    has_license,
    has_entitlement,
    has_report,
    has_billing,
    licensed_units,
    entitled_units,
    reported_units,
    billed_units,
    billed_amount,
    unit_price,
    -- The five checks of D-2 and D-10: three by units, two by presence (the answer key, D-8)
    greatest(reported_units - licensed_units, 0)                    as units_reported_beyond_licensed,
    greatest(licensed_units - reported_units, 0)                    as units_licensed_not_reported,
    greatest(entitled_units - licensed_units, 0)                    as units_entitled_beyond_licensed,
    greatest(entitled_units - reported_units, 0)                    as units_entitled_beyond_reported,
    iff(reported_units > licensed_units, 1, 0)                      as is_reported_beyond_licensed,
    iff(entitled_units > licensed_units, 1, 0)                      as is_entitled_beyond_licensed,
    iff(has_billing and not has_entitlement, 1, 0)                  as is_billed_without_entitlement,
    iff(has_entitlement and not has_billing, 1, 0)                  as is_entitled_without_billing,
    iff(entitled_units > reported_units, 1, 0)                      as is_entitled_beyond_reported,
    -- The two dollar figures, at the product's unit price (design 6.3; the answer key)
    greatest(reported_units - licensed_units, 0) * unit_price       as unbilled_amount,
    greatest(entitled_units - reported_units, 0) * unit_price       as at_risk_amount
from joined

Step 2. The metrics (models/marts/subscriber_product_month_metric.yml)

Each metric is a simple sum of one row-grain column (Data Mart Design Principles: a fact carries row-grain measures, MetricFlow computes the totals); its description says what it counts, what to pair it with and the decision that defined it. One in full; the other ten have the same shape with their own column: units_reported_beyond_licensed, units_licensed_not_reported, units_entitled_beyond_licensed, units_entitled_beyond_reported, unbilled_revenue, revenue_at_risk, and the five disagreements_ counts.

      - name: revenue_at_risk
        description: "Units entitled beyond reported times the product's unit price: the amount an under-reporting audit would test, not proven use (D-10)"
        label: Revenue at risk
        type: simple
        agg: sum
        expr: at_risk_amount
        fill_nulls_with: 0

The answer-key test, layer 4, tests/assert_checks_match_answer_key.sql, in full:

-- D-8, layer 4: the reconciliation finds exactly the answer key's rows. Every answer-key row's five
-- checks and two dollar figures equal subscriber_product_month_metric's, and the table has no row in
-- the answer key's months that the answer key does not name. Returns each row that disagrees.
with answer_key as (
    select
        tenant_id, customer_id, product_code, usage_month,
        iff(reported_beyond_licensed, 1, 0)   as is_reported_beyond_licensed,
        iff(entitled_beyond_licensed, 1, 0)   as is_entitled_beyond_licensed,
        iff(billed_without_entitlement, 1, 0) as is_billed_without_entitlement,
        iff(entitled_without_billing, 1, 0)   as is_entitled_without_billing,
        iff(entitled_beyond_reported, 1, 0)   as is_entitled_beyond_reported,
        unbilled_dollars, at_risk_dollars
    from {{ ref('seed_reconciliation_answer_key') }}
),
found as (
    select
        client.client_id as tenant_id, subscriber.subscriber_id as customer_id, product.product_code,
        spm.usage_month,
        spm.is_reported_beyond_licensed, spm.is_entitled_beyond_licensed, spm.is_billed_without_entitlement,
        spm.is_entitled_without_billing, spm.is_entitled_beyond_reported,
        spm.unbilled_amount, spm.at_risk_amount
    from {{ ref('subscriber_product_month_metric') }} as spm
    inner join {{ ref('subscriber_dim') }} as subscriber on subscriber.subscriber_hk = spm.subscriber_hk
    inner join {{ ref('client_dim') }} as client on client.client_hk = spm.client_hk
    inner join {{ ref('product_dim') }} as product on product.product_hk = spm.product_hk
    where spm.usage_month in (select usage_month from answer_key)
)

select
    coalesce(answer_key.customer_id, found.customer_id) as customer_id,
    coalesce(answer_key.product_code, found.product_code) as product_code,
    case when answer_key.customer_id is null then 'found, not in the answer key'
         when found.customer_id is null then 'in the answer key, not found'
         else 'values differ' end as finding
from answer_key
full outer join found
    on found.tenant_id = answer_key.tenant_id
    and found.customer_id = answer_key.customer_id
    and found.product_code = answer_key.product_code
    and found.usage_month = answer_key.usage_month
where answer_key.customer_id is null
    or found.customer_id is null
    or found.is_reported_beyond_licensed   <> answer_key.is_reported_beyond_licensed
    or found.is_entitled_beyond_licensed   <> answer_key.is_entitled_beyond_licensed
    or found.is_billed_without_entitlement <> answer_key.is_billed_without_entitlement
    or found.is_entitled_without_billing   <> answer_key.is_entitled_without_billing
    or found.is_entitled_beyond_reported   <> answer_key.is_entitled_beyond_reported
    or found.unbilled_amount <> answer_key.unbilled_dollars
    or found.at_risk_amount  <> answer_key.at_risk_dollars
