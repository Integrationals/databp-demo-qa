2. Logic areas

LA-1 The subscriber's source rows and match (silver subscriber)

Dimensions: the source system, DataBP, Salesforce or the usage system, and whether its carried code names a DataBP customer (yes or no). Brute force 6. Collapse: DataBP's own source row always names itself, so DataBP unmatched cannot occur: 5 paths. Design D-1, D-3, D-5.

LA-2 Source rows per key (silver subscriber)

Dimensions: the system and whether it has one source row or two on one key. Brute force 6. Collapse: DataBP's source row is its own customer and the usage system's source rows are distinct by code, so only Salesforce can name a key twice: 2 paths. Design D-1, D-6.

LA-3 The subscriber's name (silver subscriber)

Dimension: the Salesforce customer's name against DataBP's: equal, different, or no Salesforce source row. Brute force 3; no collapse. Design D-3.

LA-4 The product's source rows and match (silver product)

The dimensions of LA-1 for products: DataBP's product, Product2 or the usage system, matched or not. Brute force 6; collapse to 5 for the same reason. Design D-2, D-4.

LA-5 Source rows per key (silver product)

The dimensions of LA-2 for products; only Product2 can name a key twice: 2 paths. Design D-2, D-6.

LA-6 The product's name (silver product)

Product2's name against DataBP's: equal, different, or no Product2 source row. Brute force 3; no collapse. Design D-4.
