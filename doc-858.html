1. Purpose and grounding recap

This guide implements Silver merged entities: Design, knowledge 111 item 856 v1 approved and does not relitigate its decisions.

Design decision Settled rule used by the implementation
D-1 The subscriber's resolution as CTEs inside silver subscriber: source rows from DataBP, Salesforce and the usage system, matched on the carried subscriber_code, counted per system; every key generate_surrogate_key of that code; a source row with no DataBP customer created and flagged
D-2 The same inside silver product, on the carried product_key_code
D-3 The merged subscriber: one row per key, DataBP's values, Salesforce's id and name, months reported, source-row counts, created and name flags
D-4 The merged product the same way, with Product2's id and name
D-5 The transaction tables unchanged: their keys from their own carried codes, the same values
D-6 Three warnings: created rows, a system naming one key twice, names that differ
D-7 subscriber_dim and product_dim add the Salesforce name and the system flags; no existing column changes
D-8 The source data as it is; the unit tests carry the created, double and differing rows
D-9 Promotion by a reviewed pull request, clones before the Production job, the job by hand; $1,410 unchanged

Code in this guide is an illustrative pattern: more than pseudocode, less than shipping code. Do not copy it into the repo; implement it against the branch. Development is done when the output is shown correct against real data, per K#12 I#26.

Step 1. The branch, from databp-dbt main at 3a04599, named as Manager's task 2289 names it (Standard: Branching under squash merges, knowledge 12 item 47, 3.2a). Then the unit tests of section 6, written before the models change, and build row 1: four fail for the missing columns.

Step 2. models/silver/subscriber.sql rewritten as the resolution's CTEs and the merge (D-1, D-3, G-1 to G-4), the steps of the reference's skool_person_resolution: source rows, match on the code, counts per system, one row per code.

-- Silver subscriber: DataBP's customer merged with Salesforce's and the usage system's (design 856, D-1, D-3).
-- The resolution's steps, after the reference architecture's resolution view: source rows, match, counts, one row per code.
with databp as (
    select * from {{ ref('stg_databp__customer') }} where not is_deleted
),

salesforce as (
    select * from {{ ref('stg_databp__sfdc_account') }} where not is_deleted
),

usage_reported as (
    select subscriber_code, any_value(client_code) as client_code,
           min(usage_month) as first_month_reported, max(usage_month) as last_month_reported
    from {{ ref('stg_databp__usage_usage_declaration') }}
    where not is_deleted
    group by subscriber_code
),

source_rows as (
    select 'DATABP' as source_system, subscriber_code, client_code from databp
    union all
    select 'SALESFORCE', subscriber_code, client_code from salesforce
    union all
    select 'USAGE', subscriber_code, client_code from usage_reported
),

matched as (
    select
        subscriber_code,
        any_value(client_code)                           as client_code,
        count_if(source_system = 'DATABP')             as databp_source_rows,
        count_if(source_system = 'SALESFORCE')         as salesforce_source_rows,
        count_if(source_system = 'USAGE')              as usage_source_rows
    from source_rows
    where subscriber_code is not null
    group by subscriber_code
),

salesforce_first as (
    select * from salesforce
    qualify row_number() over (partition by subscriber_code order by account_id) = 1
)

select
    {{ dbt_utils.generate_surrogate_key(["matched.subscriber_code"]) }}                       as subscriber_hk,
    case when matched.client_code is not null
         then {{ dbt_utils.generate_surrogate_key(["matched.client_code"]) }} end             as client_hk,
    databp.customer_id                                                                         as subscriber_id,
    databp.customer_name                                                                       as subscriber_name,
    databp.email,
    salesforce_first.account_id                                                                as salesforce_customer_id,
    salesforce_first.account_name                                                              as salesforce_customer_name,
    usage_reported.first_month_reported,
    usage_reported.last_month_reported,
    matched.databp_source_rows,
    matched.salesforce_source_rows,
    matched.usage_source_rows,
    matched.databp_source_rows = 0                                                                  as is_created,
    coalesce(salesforce_first.account_name <> databp.customer_name, false)                     as name_differs,
    databp.updated_at,
    databp.subscriber_hdiff,
    databp.landed_at
from matched
left join databp           on databp.subscriber_code = matched.subscriber_code
left join salesforce_first on salesforce_first.subscriber_code = matched.subscriber_code
left join usage_reported   on usage_reported.subscriber_code = matched.subscriber_code

Build row 2 after step 3: the subscriber's unit tests pass. Customer 23's key is unchanged: generate_surrogate_key of DATABP|CUSTOMER|3|23, as in 2290.

8. Decisions recorded in this guide

ID Weed-level choice Rationale
G-1 A source row with a null code names nothing A row naming no DataBP identifier has nothing to match on
G-2 When Salesforce names one key twice, the row carries the lowest id and name; the count shows the second One row per key; the warning surfaces it
G-3 A created row's DataBP columns, id, name, email, hdiff and update time, are null DataBP has no row for it
G-4 client_hk comes from the source rows' client_code Every source row carries the tenant, so a created row has its client too
G-5 The dims' flags are derived: in Salesforce when Salesforce's count is above 0, in usage likewise The counts stay in silver; gold shows yes or no
G-6 The count test compares each merged table with the distinct non-null codes across its staging sources A source against a target, never an expected count
