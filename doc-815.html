1. Purpose and grounding recap

This guide implements Entitlement and billing reconciliation: design document, knowledge 111 item 806 v38 and does not relitigate its decisions.

Design decision Settled rule used by the implementation
D-6 An invoice item carries its product; the header's columns ride on each item
D-7 A license is a Contract with its won Opportunity's line items; silver keeps the chain whole and leaves the Activated and Closed Won filters to gold
D-11 The product's code is the identifier shared by the platform, Salesforce and usage reporting
D-16 Void invoices are excluded in gold; silver keeps invoice_status
D-17 Change times are each table's updated_at; an item's is the later of its own and its invoice's
D-18 Medallion layers: bronze is the connector's copies, silver one table per source document, gold the mart
D-19 Seven silver tables, each keyed by md5 of its business key qualified by its issuer's namespace
D-20 Hashing happens in silver; staging only renames and carries the deleted flag; business_key takes keys of several parts
D-21 Mart tables by suffix: dim_client becomes client_dim

Code in this guide is an illustrative pattern: more than pseudocode, less than shipping code. Do not copy it into the repo; implement it against the branch. Development is done when the output is shown correct against real data, per K#12 I#26.

5. Ordered implementation steps

Step 1. Keys of several parts (macros/business_key.sql)

Changes the existing macro; its one consumer, stg_databp__client, stops calling it in step 3, and the seven silver models call it in step 4. A single id keeps its old output, so the change is backward compatible. Design D-19, D-20. Exemplar: the file itself.

{#- A row's business key inside its issuer's namespace (Harbor's pattern, D-19):
    ISSUER|TABLE|part, or ISSUER|TABLE|part1|part2 when id_expr is a list of parts (D-20). -#}
{% macro business_key(source_code, table_code, id_expr) -%}
    {%- set parts = id_expr if id_expr is not string else [id_expr] -%}
    '{{ source_code }}|{{ table_code }}'
    {%- for part in parts %} || '|' || cast({{ part }} as varchar){% endfor %}
{%- endmacro %}

Step 2. Sources for the eleven new landed tables (models/staging/_sources.yml)

Instantiates Source Staging (knowledge 14 item 37). Three sources, one per source system (D-3, D-4): databp_src (DATABP_SRC_DBO), databp_sfdc (DATABP_SFDC_DBO), databp_usage (DATABP_USAGE_DBO). Each table is declared by its uppercase identifier, with not_null on its source key. Exemplar: the existing client entry. Delta per table: its name, identifier and key column.

Step 3. Staging views (models/staging/stg_databp__*.sql and .yml)

Instantiates Source Staging (knowledge 14 item 37). One view per landed table, every source column kept and renamed to snake case, plus is_deleted, landed_at and changed_at from the connector's columns; no hash (D-20). Exemplar: models/staging/stg_databp__client.sql, rewritten first in this shape. Names follow Object Naming (knowledge 12 item 147, section 2, row 5) with this project's prefix (guide decision G-1): platform tables stg_databp__

, Salesforce stg_databp__sfdc_
, usage reporting stg_databp__usage_
.

The Salesforce instance shows the renames; the other eleven are the same shape with their own columns:

with landed as (
    select * from {{ source('databp_sfdc', 'account') }}
)

-- Bronze to staging: renamed, one row per landed row, with the deleted flag; keys are hashed in silver (D-20)
select

Step 4. Silver tables (models/silver/*.sql), keys hashed in the issuer's namespace

First instance in this repository, aligned with the reference architecture. dbt_project.yml gains the silver folder, schema silver, materialized table. Every silver model reads staging rows not deleted, builds its keys with business_key and md5 (D-19), and adds change_hash and landed_at (design 6.1). subscriber is the first instance, in full:

-- Silver subscriber: the platform's customer, keyed in the platform's namespace (D-19)
select
    md5({{ business_key('DATABP', 'CUSTOMER', ['tenant_id', 'customer_id']) }})  as subscriber_hk,
    md5({{ business_key('DATABP', 'CLIENT', 'tenant_id') }})                     as client_hk,
    customer_id                                                                  as subscriber_id,
    customer_name                                                                as subscriber_name,
    updated_at,
    md5(coalesce(customer_name, ''))                                             as change_hash,
    landed_at
from {{ ref('stg_databp__customer') }}
where not is_deleted

Delta instances. product: key DATABP, PRODUCT, tenant_id, product_code; change_hash over product_name and unit_price. client: key DATABP, CLIENT, client_id; no updated_at at the source. entitlement: product_hk looked up through product by tenant_id and product_id, null when no product matches, which the not_null test catches (LA-6). invoice_item: the header joined on tenant_id and invoice_id; product_hk as entitlement's; updated_at the greater of header and item (D-17).

license_line, the variation that conforms Salesforce to the platform: the chain joined inside, and its subscriber and product keys built in the platform's namespace from Salesforce's own columns (D-7, D-19). Each of line_item, opportunity, contract, account and product2 is a CTE over its staging view, rows not deleted:

select
    md5({{ business_key('SFDC', 'OPPORTUNITYLINEITEM', 'line_item.opportunity_line_item_id') }})    as license_line_hk,
    md5({{ business_key('DATABP', 'CLIENT', 'account.tenant_id') }})                                as client_hk,
    md5({{ business_key('DATABP', 'CUSTOMER', ['account.tenant_id', 'account.subscriber_id']) }})   as subscriber_hk,
    md5({{ business_key('DATABP', 'PRODUCT', ['product2.tenant_id', 'product2.product_code']) }})   as product_hk,
    contract.contract_id,
    contract.start_date      as contract_start_date,
    contract.end_date        as contract_end_date,
    contract.status          as contract_status,
    opportunity.opportunity_id,
    opportunity.stage_name   as opportunity_stage,
    line_item.quantity       as licensed_units,
    line_item.unit_price     as licensed_unit_price,
    md5(contract.status || '|' || opportunity.stage_name || '|' || cast(contract.start_date as varchar) || '|'
        || cast(contract.end_date as varchar) || '|' || cast(line_item.quantity as varchar) || '|'
        || cast(line_item.unit_price as varchar)) as change_hash,
    line_item.landed_at
from line_item
inner join opportunity on opportunity.opportunity_id = line_item.opportunity_id
inner join contract    on contract.contract_id = opportunity.contract_id
inner join account     on account.account_id = contract.account_id
inner join product2    on product2.product2_id = line_item.product2_id

usage_report, the variation that keeps one report per month (D-2):

with report as (
    select * from {{ ref('stg_databp__usage_usage_declaration') }} where not is_deleted
    qualify row_number() over (
        partition by tenant_id, customer_id, product_code, usage_month
        order by declared_at desc, declaration_id desc
    ) = 1
)

select
    md5({{ business_key('USAGE', 'USAGE_DECLARATION', ['tenant_id', 'declaration_id']) }})  as usage_report_hk,
    md5({{ business_key('DATABP', 'CLIENT', 'tenant_id') }})                                as client_hk,
    md5({{ business_key('DATABP', 'CUSTOMER', ['tenant_id', 'customer_id']) }})             as subscriber_hk,
    md5({{ business_key('DATABP', 'PRODUCT', ['tenant_id', 'product_code']) }})             as product_hk,
    declaration_id,
    usage_month,
    declared_units                                                                          as reported_units,
    declared_at,
    md5(cast(declared_units as varchar) || '|' || cast(declared_at as varchar))             as change_hash,
    landed_at
from report

-- Layer 4, profile column 11 (D-15): an invoice with items carries the sum of its items' amounts.
-- Returns each invoice whose amount differs from its items' sum; passing returns no rows.
select
    invoice.tenant_id,
    invoice.invoice_id,
    invoice.amount,
    sum(item.amount) as items_amount
from {{ ref('stg_databp__invoice') }} as invoice
inner join {{ ref('stg_databp__invoice_item') }} as item
    on item.tenant_id = invoice.tenant_id
    and item.invoice_id = invoice.invoice_id
where not invoice.is_deleted and not item.is_deleted
group by invoice.tenant_id, invoice.invoice_id, invoice.amount
having invoice.amount <> sum(item.amount)

8. Decisions recorded in this guide

ID Weed-level choice Rationale
G-1 Staging names keep the exemplar stg_databp__client for the platform and add the source system for the others: stg_databp__sfdc_, stg_databp__usage_
Object Naming (section 2, row 5) names the source; the platform's tables already read as this project's own, and renaming the exemplar would touch a working model for no reader's gain
G-2 Silver carries landed_at, the connector's insert time The reference platform's integrators carry their load time; client_dim's metric needs a time dimension; written into the design's map, 6.1
G-3 license_line joins its chain inside: a line item missing its Opportunity, Contract, Account or Product2 is dropped A line item without its chain is no license (D-7); the count reconciliation would show the drop
G-4 change_hash is md5 of the non-key columns joined by a vertical bar The exemplar's form, widened to several columns
G-5 Two usage reports with the same declared_at: the higher declaration_id wins A choice for the case the design leaves open, so the result is the same on every run
G-6 Staging keeps the seven rejected columns; silver drops them Staging is one view per landed table, column for column (D-20); the profile's verdicts apply where columns are chosen, in silver
G-7 The landing reconciliation is a script in generator/, beside run.py, which it reuses It reads SQL Server through the agent function, which dbt cannot reach
G-8 The code was written and proven in development before this guide, on Ray's pre-authorization to write the guide and build to silver The guide shows the code that ran; nothing is merged before Ray reviews
